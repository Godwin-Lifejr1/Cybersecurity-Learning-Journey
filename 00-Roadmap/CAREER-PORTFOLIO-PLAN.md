# Career Portfolio Plan

## Goal

Build a public cybersecurity portfolio that demonstrates employable ability rather than simply listing courses completed.

Target entry-level and junior opportunities:
- SOC Analyst
- Security Operations / Cybersecurity Analyst
- Junior Network Security Analyst
- IT Support / Security Operations
- Junior Penetration Testing / Security Testing roles

This repository must never claim expertise that has not been demonstrated. Completed milestones require practical evidence, a reproducible lab, a report, or a working project.

## What an employer should see

1. What does Godwin know?
2. What has he actually built or investigated?
3. Can he use security tools without blindly following commands?
4. Can he troubleshoot when the first attempt fails?
5. Can he explain technical findings clearly?
6. Does he understand security boundaries and responsible testing?
7. Is there evidence of progression?

## Portfolio pillars

### 1. Networking foundation
IPv4/CIDR, routing, ARP, TCP/UDP, DNS/DHCP, ICMP, HTTP/HTTPS, tcpdump, Wireshark and troubleshooting.

Current evidence:
- DNS packet capture and Wireshark analysis
- TCP connection lifecycle analysis
- Gateway and neighbour-table observations

### 2. Linux and systems
Planned evidence:
- Filesystem and permissions labs
- Processes and services
- Log analysis
- Users/groups
- SSH and secure configuration
- Linux hardening checklist

### 3. Python and security automation
Planned projects:
- Log parser
- IOC extraction utility
- File integrity checker
- Network/asset inventory helper
- Security-report automation

### 4. Defensive security
Planned projects:
- Centralised log collection
- Detection rules
- Alert investigation
- Incident timeline
- Incident response report
- MITRE ATT&CK mapping where appropriate

### 5. Ethical hacking and web security
Use intentionally vulnerable applications or explicitly authorised systems only.

Each assessment will contain:
- Scope
- Methodology
- Evidence
- Finding
- Impact
- Remediation
- Retest result

### 6. Cloud and identity security
Planned evidence:
- IAM and least privilege
- Cloud logging and monitoring
- Network controls
- Secrets management
- Cloud threat modelling

## Project standard

A strong project should contain:
1. README
2. Objective
3. Scope and lab architecture
4. Problem or threat statement
5. Tools and technologies
6. Implementation or investigation
7. Evidence
8. Findings
9. Troubleshooting
10. Security implications
11. Remediation
12. Lessons learned
13. Limitations
14. Reproduction instructions

## Evidence standard

Never upload secrets, passwords, API keys, private keys, tokens, personal data, or unnecessarily sensitive network details.

Sanitise public screenshots where necessary.

Raw packet captures remain local unless deliberately reviewed and sanitised.

## GitHub growth strategy

Learn -> Practise -> Troubleshoot -> Document -> Build -> Review -> Publish

A lesson is not automatically a portfolio project.

A finished project must demonstrate a skill that can be discussed in an interview.

## Career readiness

Foundation -> Practical -> Portfolio -> Interview readiness

For every major project, be able to explain why it was built, how it works, what failed, how it was diagnosed, what the evidence proves, and what would be improved.
