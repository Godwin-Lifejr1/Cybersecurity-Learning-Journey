# Cybersecurity Learning Roadmap

## Study rhythm
Target: 3–4 hours per day, with extra practice whenever a concept needs it.

Suggested session:
- 45–60 minutes: concepts and notes
- 90–120 minutes: guided hands-on lab
- 30 minutes: review, troubleshooting, and evidence
- 15–30 minutes: GitHub documentation and reflection

## Phases

### Phase 1 — Networking fundamentals
- OSI and TCP/IP models
- IPv4, subnet masks, CIDR, private/public addresses
- MAC addresses, ARP, switches, routers, default gateways
- TCP vs UDP, ports, sockets
- DNS, DHCP, HTTP/HTTPS, ICMP
- Routing, NAT, firewalls, VPN fundamentals
- Diagnostics: ip, ping, traceroute/tracepath, ss, dig/nslookup, tcpdump, Wireshark, and Nmap in authorised labs

**Milestone:** Explain and troubleshoot a small lab network and document packet observations.

### Phase 2 — Linux fundamentals
- Filesystem, navigation, files, permissions, users, groups
- Processes, services, logs, package management
- Networking commands and shell fundamentals
- SSH basics and safe system administration

### Phase 3 — Python and automation
- Variables, data types, conditions, loops, functions
- Files, exceptions, modules, virtual environments
- Parsing logs and structured data
- Small defensive automation scripts

### Phase 4 — Security foundations and hardening
- Confidentiality, integrity, availability
- Threats, vulnerabilities, risk, and controls
- Authentication, authorisation, least privilege
- Patching, secure configuration, backups, encryption
- Threat modelling and security documentation

### Phase 5 — Network analysis
- Packet capture and protocol analysis
- Baseline network behaviour
- Firewall rules and segmentation concepts
- Service discovery in isolated, authorised labs
- Documenting findings and limitations

### Phase 6 — Defensive security
- Logs and telemetry
- Detection engineering fundamentals
- SIEM concepts and alert triage
- Incident response lifecycle
- Evidence handling and incident reports

### Phase 7 — Web security and ethical hacking
- HTTP requests and responses
- Authentication and session concepts
- Common web vulnerability classes
- Safe testing with intentionally vulnerable training applications
- Findings, impact, remediation, and retesting

### Phase 8 — Vulnerability management
- Authorised asset inventory and scanning
- Validation and false-positive handling
- Severity, likelihood, impact, and prioritisation
- Remediation plans and retesting

### Phase 9 — Cloud, identity, and access
- Cloud shared-responsibility concepts
- IAM and least privilege
- Network controls, audit logs, storage security
- Secrets management and cloud threat modelling

### Phase 10 — Capstones
- Network troubleshooting report
- Linux hardening checklist
- Python log parser
- Defensive detection and incident report
- Authorised web-lab assessment report
- Final portfolio review

## Completion criteria
A phase is complete when concepts are explained in the learner's own words, labs are reproducible, results and troubleshooting are documented, and safety boundaries are respected.
